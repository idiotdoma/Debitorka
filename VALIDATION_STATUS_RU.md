# Статус проверки комплекта серверной части

Дата подготовки: 28 октября 2026 г.

## Что проверено локально

- TypeScript-синтаксис и согласованность подготовленного адаптера `src/lib/serverApi.ts` прошли локальную проверку `tsc -p tsconfig.check.json` с временной декларацией интерфейса Supabase. Это проверка самого адаптера, а не полная проверка проекта.
- Проведена статическая сверка состава SQL-миграции: таблицы, политики RLS, ключевые RPC и представления включены в один транзакционный migration-файл.
- SQL-миграция содержит запрет создания объектов ролями `PUBLIC`, `anon` и `authenticated` в схемах `public` и `extensions`.

## Что НЕ проверено

- Миграция не запускалась на реальном PostgreSQL/Supabase: в этой среде нет `psql`, Supabase CLI и подключённого тестового проекта.
- Миграция не прогонялась через полноценный PostgreSQL SQL-парсер.
- `serverApi.ts` не проверен против реальных типов установленного `@supabase/supabase-js`; временная декларация использовалась только для локальной проверки синтаксиса и собственных DTO.
- Не запускались реальные сценарии Supabase Auth.
- Не выполнены ручные тесты RLS двумя отдельными пользователями из разных организаций.
- Не подтверждены фактическая доставка приглашений по email и интеграция 1С.
- Новая серверная часть ещё не подключена к существующим страницам приложения и не применена к вашему проекту Supabase.

## Обязательный порядок перед использованием реальных данных

1. Создать отдельный тестовый проект Supabase.
2. Применить миграцию и устранить ошибки PostgreSQL, если они появятся.
3. Подключить frontend и проверить `typecheck`, тесты и production-сборку уже в полном проекте.
4. Создать две тестовые организации и минимум двух пользователей в каждой.
5. Проверить, что пользователь не может читать, менять или получать данные другой организации, в том числе через прямые запросы к API.
6. Проверить создание организации, приглашения, принятие и отзыв приглашения.
7. Проверить атомарный импорт: никаких записей задолженности при невалидном наборе, корректный снимок после успешного импорта, отсутствие дубликатов при повторном импорте.
8. Только после успешных проверок решать вопрос о production-развёртывании.

Этот комплект — основа для интеграции, а не подтверждение производственной готовности. Не загружайте реальные финансовые данные до выполнения проверок выше.
