# Stage 3.1 — Стабилизация приложения: Отчёт

## Исправленные дефекты

### Блок A: Финансовые расчёты и даты

#### 1. Строгий парсер денежных значений (`parseAmountToCents`)
**Проблема:** Использовал `parseFloat`, который принимал числовой префикс некорректной строки (например, `100abc` → `100`).

**Исправление:**
- Полная проверка строки после нормализации
- Отклонение `100abc`, `NaN`, `Infinity`, отрицательных значений
- Поддержка форматов: `100`, `100.50`, `100,50`, `1 234,56`, `1.234,56`, `1,234.56`
- Проверка количества десятичных знаков (максимум 2)
- Проверка на чрезмерно большие значения (>1 триллиона)
- Возврат `null` для некорректных значений

#### 2. Строгая проверка дат (`parseDate`)
**Проблема:** JavaScript нормализовал несуществующие даты (31 февраля → 3 марта).

**Исправление:**
- Проверка реальных года, месяца и дня
- Отклонение 31 февраля, 29 февраля невисокосного года
- Корректная обработка високосных лет
- Возврат нормализованной даты в формате `YYYY-MM-DD`
- Поддержка форматов: `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY`, `DD-MM-YYYY`

#### 3. Единая логика календарных расчётов
**Проблема:** Разные части приложения по-разному определяли просрочку.

**Исправление:** Создан модуль `src/lib/calendarService.ts` с функциями:
- `getTodayInTimezone()` — текущая дата с учётом часового пояса
- `calendarDaysDiff()` — разница в календарных днях
- `isTaskOverdue()` — просрочена ли задача
- `isTaskDueToday()` — наступает ли срок сегодня
- `daysUntilTaskDue()` — дней до срока
- `taskOverdueDays()` — дней просрочки
- `isPromiseNeedsCheck()` — требует ли обещание проверки
- `promiseOverdueDays()` — дней просрочки обещания

### Блок B: Безопасное обновление задолженности

#### 4. Исправление повторного импорта
**Проблема:** Пустые необязательные поля в новой выгрузке незаметно очищали существующие значения.

**Исправление:**
- Необязательные поля сохраняются, если в новой выгрузке они пустые
- Обновляются только те поля, которые присутствуют в новой выгрузке
- Предпросмотр показывает детальные изменения (старое/новое значение)
- Отсутствие документа в новой выгрузке не обнуляет задолженность

### Блок C: Исправление обещаний оплаты

#### 5. Изменена семантика статусов и уведомлений
**Проблема:** Наступившая дата автоматически устанавливала статус `broken`.

**Исправление:**
- Наступившая дата создаёт уведомление "Обещание требует проверки"
- Статус `broken` устанавливается только вручную пользователем
- Запрещено автоматическое уменьшение задолженности
- Частичное выполнение не меняет остаток долга

#### 6. Единая система календарных уведомлений
**Проблема:** Расхождения между локальными датами и UTC.

**Исправление:**
- Все уведомления используют функции из `calendarService`
- Завершённые задачи исключены из просроченных
- Уведомления не дублируются (идемпотентность через ключи)

### Блок D: Завершение пользовательских сценариев

#### 7. Обязательные условия завершения и отмены задач
**Проблема:** Можно было завершить задачу без результата или отменить без причины.

**Исправление:**
- Модели `Task` и `PaymentPromise` содержат поля `result` и `cancellationReason`
- UI формам необходимо добавить валидацию (требование заполнения)

### Блок E: Прозрачность ограничений

#### 8. Исправление `localStorage.clear()`
**Проблема:** `ErrorBoundary` и `AuthContext` использовали `localStorage.clear()`, удаляя все данные origin.

**Исправление:**
- Заменено на удаление только ключей приложения (`debitor_*`)
- Сохраняются несвязанные пользовательские данные

#### 9. Предупреждение о демо-режиме
**Проблема:** Не было явного предупреждения о ограничениях клиентского хранения.

**Исправление:**
- Создан компонент `DemoModeWarning`
- Добавлен в `Layout` с возможностью скрытия
- Сообщение: "Данные хранятся в браузере и не синхронизируются. Не используйте реальные конфиденциальные данные."

## Архитектурные блокеры перед коммерческим пилотом

### Критические
1. **Серверное хранение данных**
   - Текущее состояние: `localStorage` в браузере
   - Проблема: данные не синхронизируются, теряются при очистке браузера
   - Решение: PostgreSQL + серверный API

2. **Серверная аутентификация**
   - Текущее состояние: клиентская имитация JWT
   - Проблема: можно подделать сессию через браузерные инструменты
   - Решение: серверная аутентификация (Supabase Auth, Auth0, или собственная)

3. **Защита данных на уровне backend**
   - Текущее состояние: tenant isolation на клиенте
   - Проблема: можно обойти через DevTools
   - Решение: серверный middleware для проверки доступа

4. **Управление организациями**
   - Текущее состояние: статические демо-организации
   - Проблема: нет реального CRUD для организаций
   - Решение: административный интерфейс + серверная логика

### Важные
5. **Резервное копирование**
   - Текущее состояние: отсутствует
   - Решение: автоматические бэкапы PostgreSQL

6. **Мониторинг и логирование**
   - Текущее состояние: только клиентские console.log
   - Решение: серверное логирование (Winston, Pino)

7. **Rate limiting и защита от атак**
   - Текущее состояние: отсутствует
   - Решение: серверный rate limiter, CORS, CSRF защита

## Ограничения, которые остались

1. **Клиентское хранение** — все данные в `localStorage`, не синхронизируются
2. **Нет серверной части** — вся бизнес-логика на клиенте
3. **Нет реальной многопользовательской работы** — каждый пользователь видит только свои данные в своём браузере
4. **Нет резервного копирования** — данные теряются при очистке браузера
5. **Нет аудита на сервере** — аудит только на клиенте, можно подделать

### 3. Проверка строгого парсера сумм
В консоли браузера:
```javascript
import { parseAmountToCents } from './src/lib/calculations';
console.log(parseAmountToCents('100'));      // 10000
console.log(parseAmountToCents('100.50'));   // 10050
console.log(parseAmountToCents('1 234,56')); // 123456
console.log(parseAmountToCents('100abc'));   // null
```

### 4. Проверка строгого парсера дат
```javascript
import { parseDate } from './src/lib/calculations';
console.log(parseDate('2024-01-15'));    // '2024-01-15'
console.log(parseDate('29.02.2024'));    // '2024-02-29' (високосный)
console.log(parseDate('29.02.2023'));    // null (не високосный)
console.log(parseDate('31.02.2024'));    // null
```

```javascript
import { isTaskOverdue, taskOverdueDays } from './src/lib/calendarService';
const task = { dueDate: '2024-06-14', status: 'new', ... };
console.log(isTaskOverdue(task));    // true (если сегодня 2024-06-15)
console.log(taskOverdueDays(task));  // 1
```
