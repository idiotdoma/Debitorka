# PROMPT ДЛЯ АГЕНТА: подключить готовую серверную часть «Дебиторки»

В корне проекта находится комплект серверной части Supabase в папке `debitorka_server_backend` либо пользователь прикрепил архив `debitorka-server-backend.zip`.

Твоя задача — интегрировать подготовленные файлы в существующее приложение. Не переписывай SQL-миграцию с нуля и не придумывай другую архитектуру, не объяснив конкретную техническую несовместимость.

## Сделай по порядку

1. Скопируй `supabase/` в корень репозитория, не перезаписывая существующие миграции. Если номера миграций конфликтуют, переименуй миграцию по принятому в проекте формату и обнови инструкции.
2. Скопируй `src/lib/supabaseClient.ts`, `src/lib/serverApi.ts`, `src/types/backend.ts` в соответствующие директории.
3. Перенеси `.env.example` в корень, сохранив существующий файл и объединив переменные. Не создавай настоящий `.env.local` и не проси публиковать секреты.
4. Прочитай `README_RU.md` и `docs/FRONTEND_INTEGRATION.md`.
5. Проверь TypeScript и совместимость нового API с моделями текущего проекта. Исправляй ошибки адаптера, но не добавляй фиктивную авторизацию.
6. Подключи `AuthContext.tsx` к Supabase Auth. Удали из активного production-пути проверку паролей через `hashPassword` / `verifyPassword`, `generateToken` и сохранение сессии в `localStorage`. Не обязательно сразу удалять старый `store.ts`, но не используй его как fallback для тех же сущностей, которые уже читаются/пишутся на сервер.
7. Подключи страницы регистрации и входа к Supabase Auth.
8. После входа загружай членства через `serverApi.getMemberships()`. Если пользователь не состоит ни в одной организации, предложи создать организацию через `serverApi.createOrganization()`. Не назначай owner на клиенте.
9. Подключи управление сотрудниками/командами к RPC и API из `serverApi.ts`. Добавь экран принятия приглашения: токен читается из URL fragment (`#token=...`), после входа вызывается `acceptInvitation(token)`, затем fragment немедленно удаляется из адресной строки. Не сохраняй токен в localStorage и не логируй его.
10. Начни с переключения пользователей, организаций, команд и задач. Затем переводи задолженность, контакты, обещания оплаты, уведомления и отчёты. Для финансовых записей обязательно используй текущие ограничения RLS.
11. Для ручного импорта используй только атомарный сценарий: `createImportBatch` → полная проверка всех строк → `commitManualImport`; при ошибках валидации используй `failImportBatch`. Не используй прямые `insert/upsert/update` для таблицы `debt_records`, не меняй `import_batches.status` с клиента и не вызывай функцию создания снимков напрямую.
12. Количество строк в `createImportBatch` должно совпадать с полным количеством строк данных, которые будут переданы в `commitManualImport`. Не делай частичный импорт, если в наборе есть ошибки.
13. Не отправляй `service_role` key в браузер. Если операция требует service role, реализуй её только в доверенной серверной среде и документируй секреты через серверное окружение.
14. Не переключай 1С и реальные интеграционные секреты до отдельной безопасной реализации backend sync worker / secret vault.
15. Не мигрируй localStorage автоматически. Сделай отдельный сценарий экспорта, предпросмотра и импорта локальных данных, если это требуется для сохранения текущего тестового состояния.
16. Запусти `npm run typecheck`, существующие тесты и `npm run build`. Исправь ошибки, относящиеся к твоим изменениям. Не отключай проверки и не удаляй тесты.
17. Не утверждай, что RLS проверен, если не выполнял проверку минимум двумя аккаунтами в разных организациях. Если Supabase credentials недоступны, укажи это явно и дай точный перечень оставшихся шагов.

## Основные ограничения

- Не переписывай существующие страницы целиком без необходимости.
- Не добавляй фиктивные данные в production UI.
- Не оставляй localStorage и Supabase параллельными источниками истины для одних сущностей.
- Не обходи политики RLS, чтобы скрыть ошибки интерфейса.
- Не доверяй organizationId, роли или userId, приходящим из клиентского состояния.
- Не меняй бухгалтерскую задолженность из-за обещания оплаты.
- Не храни в таблице `integration_connections.config` пароли, токены и API-ключи.

## Итоговый отчёт

Укажи изменённые файлы, применённые миграции, подключённые страницы, результаты typecheck/test/build и ручные проверки изоляции данных. Разделяй подтверждённые результаты и непроверенные из-за отсутствия Supabase-проекта.
