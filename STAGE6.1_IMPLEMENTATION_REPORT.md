## Архитектурные ограничения

### Текущее состояние
- **Хранение данных**: localStorage (демонстрационный режим)
- **Аутентификация**: клиентская (не для production)
- **Приглашения**: токены генерируются, но email не отправляются
- **Аудит**: записи хранятся локально

### Для production необходимо
1. **Серверная часть** (Node.js + Express или аналог)
2. **База данных** (PostgreSQL с миграциями)
3. **Серверная аутентификация** (JWT + bcrypt)
4. **RLS политики** для изоляции данных
5. **Почтовый сервис** для отправки приглашений
6. **Безопасное хранение секретов** (environment variables на сервере)

- **Владелец**: `owner@demo.ru` / `owner123`
- **Руководитель**: `manager@demo.ru` / `manager123`
- **Сотрудник**: `employee@demo.ru` / `employee123`

### Проверка ролевых кабинетов
1. Войдите как `manager@demo.ru` → откроется "Кабинет руководителя"
2. Войдите как `employee@demo.ru` → откроется "Мои задачи"

## Инструкции для пользователей

### Создание первой организации
1. Откройте приложение
2. Нажмите "Регистрация"
3. Заполните форму (название организации, имя, email, пароль)
4. Первый пользователь автоматически получает роль `owner`

### Приглашение сотрудников
1. Войдите как владелец или администратор
2. Перейдите в "Управление компанией" → "Сотрудники"
3. Нажмите "Пригласить"
4. Введите email и выберите роль
5. Нажмите "Отправить приглашение"
6. **В демо-режиме**: приглашение создаётся, но email не отправляется
7. **В production**: сотрудник получит email со ссылкой для принятия приглашения

### Управление командами
1. Перейдите в "Управление компанией" → "Команды"
2. Нажмите "Создать команду"
3. Введите название и описание
4. Назначьте руководителя (через редактирование пользователя)

## Известные проблемы и ограничения

### Критические (для production)
1. **Нет серверной части** - все данные в localStorage
2. **Нет реальной аутентификации** - клиентская проверка паролей
3. **Нет отправки email** - приглашения не доставляются
4. **Нет RLS** - изоляция данных только на клиенте

### Важные
1. **Размер бандла > 500 kB** - рекомендуется code splitting
2. **Нет тестов** - автоматические тесты не восстановлены
3. **Демо-режим** - ограниченная функциональность

### Незначительные
1. **Нет экспорта данных** - только импорт
2. **Нет фоновых задач** - уведомления только при открытии
