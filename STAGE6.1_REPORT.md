# Этап 6.1 — Личные кабинеты, роли пользователей и управление сотрудниками

## Что реализовано

### 1. Система ролей и разрешений

**Реализованные роли:**
- `owner` — Владелец организации (полный доступ)
- `admin` — Администратор (управление пользователями и настройками)
- `manager` — Руководитель команды (управление командой и задачами)
- `finance` — Финансовый специалист (финансовая аналитика)
- `employee` — Сотрудник (работа с задачами и контрагентами)
- `viewer` — Наблюдатель (только просмотр)

**Матрица разрешений** (`src/lib/permissions.ts`):
- `debts:view_all` / `debts:view_assigned` — просмотр задолженности
- `tasks:view_all` / `tasks:view_team` / `tasks:view_own` — просмотр задач
- `tasks:create` / `tasks:assign` / `tasks:edit_own` — управление задачами
- `teams:manage` — управление командами
- `users:invite` / `users:manage` — управление пользователями
- `organization:settings` — настройки организации
- `finance:view_analytics` — финансовая аналитика
- `ai:use` — использование ИИ-помощника

### 2. Модели данных

**`src/types/models.ts`:**
- `Organization` — организация с часовой зоной
- `User` — пользователь с ролью, командой, статусом активности
- `Team` — команда с руководителем
- `Invitation` — приглашение с токеном, сроком действия, статусом
- `DebtRecord` — задолженность
- `Task` — задача

### 3. Хранилище с tenant isolation

**`src/lib/store.ts`:**
- `orgStore` — управление организациями
- `userStore` — управление пользователями с проверкой tenant isolation
- `authStore` — управление сессиями
- `teamStore` — управление командами
- `invitationStore` — управление приглашениями
- `debtStore` — управление задолженностями
- `taskStore` — управление задачами

**Безопасность:**
- Все операции проверяют `organizationId` через `assertTenantAccess()`
- Пользователь одной организации не может получить доступ к данным другой
- Tenant isolation применяется ко всем хранилищам

### 4. Система аутентификации

**`src/contexts/AuthContext.tsx`:**
- Вход по email и паролю
- Регистрация новой организации (первый пользователь становится `owner`)
- Проверка активности учётной записи
- Управление сессиями с временем истечения
- Автоматическое восстановление сессии при перезагрузке

### 5. Система приглашений

**`src/pages/UsersPage.tsx`:**
- Приглашение сотрудников по email
- Выбор роли при приглашении
- Генерация криптографически случайного токена
- Хранение хэша токена (не самого токена)
- Срок действия приглашения — 7 дней
- Статусы приглашений: `pending`, `accepted`, `expired`, `revoked`

### 6. Демо-данные

**`src/lib/seed.ts`:**
- Автоматическое создание демо-организации при первом запуске
- Создание команды "Отдел работы с задолженностью"
- Создание 4 демо-пользователей с разными ролями:
  - `owner@demo.ru` / `owner123` — Владелец
  - `manager@demo.ru` / `manager123` — Руководитель
  - `employee@demo.ru` / `employee123` — Сотрудник
  - `viewer@demo.ru` / `viewer123` — Наблюдатель
- Создание 5 демо-задолженностей с разными сроками просрочки

### 7. Пользовательский интерфейс

**Страницы:**
- `LoginPage` — вход и регистрация
- `DashboardPage` — дашборд с KPI-карточками
- `UsersPage` — управление сотрудниками и приглашениями

**Компоненты:**
- `Layout` — адаптивная навигация с учётом ролей
- `ErrorBoundary` — обработка ошибок с возможностью сброса данных

**Навигация зависит от роли:**
- `owner` / `admin` — полный доступ ко всем разделам
- `manager` — дашборд, команда, профиль
- `finance` — дашборд, задолженности, профиль
- `employee` — дашборд, мои задачи, профиль
- `viewer` — дашборд, профиль (только просмотр)

### 8. Утилиты безопасности

- `generateToken()` — генерация криптографически случайных токенов

- `generateId()` — генерация уникальных идентификаторов

## Архитектурные ограничения

### Текущие ограничения

1. **Клиентское хранение данных**
   - Все данные в `localStorage`
   - Нет серверной базы данных
   - Данные не синхронизируются между пользователями

2. **Клиентская аутентификация**
   - Пароли хешируются на клиенте
   - Сессии хранятся в `localStorage`
   - Нет серверной проверки токенов

3. **Нет серверной части**
   - Вся бизнес-логика на клиенте
   - Нет API для интеграции с внешними системами
   - Нет фоновых задач

### Блокеры для commercial use

1. **Серверное хранение данных**
   - Требуется PostgreSQL или аналогичная БД
   - Необходимы миграции для схемы данных
   - Нужен ORM (Prisma, Drizzle, TypeORM)

2. **Серверная аутентификация**
   - Требуется JWT с серверной валидацией
   - Необходимы httpOnly cookies для сессий
   - Нужен bcrypt для паролей на сервере

3. **Защита данных на уровне backend**
   - Tenant isolation должен проверяться на сервере
   - Необходимы Row Level Security policies (для Supabase)
   - Нужен middleware для проверки прав доступа

4. **Безопасное хранение секретов**
   - API-ключи не должны храниться на клиенте
   - Необходимо серверное хранилище секретов
   - Требуется шифрование чувствительных данных

## Инструкция по проверке

### 1. Запуск приложения
```bash
npm install
npm run dev
```

### 2. Вход в систему

**Вариант 1: Использование демо-аккаунтов**
- Владелец: `owner@demo.ru` / `owner123`
- Руководитель: `manager@demo.ru` / `manager123`
- Сотрудник: `employee@demo.ru` / `employee123`
- Наблюдатель: `viewer@demo.ru` / `viewer123`

**Вариант 2: Регистрация новой организации**
1. Нажмите "Нет аккаунта? Зарегистрировать организацию"
2. Заполните форму:
   - Название организации
   - Ваше имя
   - Email
   - Пароль
3. Вы автоматически становитесь владельцем организации

### 3. Проверка ролей

**Владелец (owner):**
- Видит все разделы навигации
- Может приглашать сотрудников
- Может управлять командами
- Имеет доступ к настройкам организации

**Руководитель (manager):**
- Видит дашборд, команду, профиль
- Может управлять своей командой
- Не видит раздел "Сотрудники" (только свою команду)

**Сотрудник (employee):**
- Видит дашборд, мои задачи, профиль
- Не видит других сотрудников
- Не может управлять командами

**Наблюдатель (viewer):**
- Видит только дашборд и профиль
- Нет доступа к управлению
- Только просмотр данных

### 4. Приглашение сотрудника

1. Войдите как `owner` или `admin`
2. Перейдите в "Сотрудники"
3. Нажмите "Пригласить"
4. Введите email нового сотрудника
5. Выберите роль
6. Нажмите "Отправить приглашение"
7. Приглашение появится в списке с статусом "Ожидает"

### 5. Проверка tenant isolation

1. Зарегистрируйте вторую организацию
2. Войдите в первую организацию
3. Попробуйте получить доступ к данным второй организации через DevTools
4. Должна появиться ошибка "FORBIDDEN"

## Что НЕ реализовано

1. **Серверная часть**
   - Нет backend API
   - Нет базы данных
   - Нет серверной аутентификации

2. **Полноценная система приглашений**
   - Нет отправки email с ссылкой приглашения
   - Нет страницы принятия приглашения
   - Нет механизма отзыва приглашений

3. **Управление командами**
   - Нет UI для создания/редактирования команд
   - Нет назначения сотрудников в команды
   - Нет иерархии команд

4. **Профиль пользователя**
   - Нет страницы профиля
   - Нет возможности изменить личные данные
   - Нет смены пароля

5. **Личные кабинеты для разных ролей**
   - Нет отдельного кабинета руководителя
   - Нет кабинета финансового специалиста
   - Нет специализированных дашбордов

## Следующие шаги

Для завершения этапа 6 и подготовки к commercial use необходимо:

1. **Реализовать серверный backend**
   - Node.js + Express или аналог
   - PostgreSQL + Prisma/Drizzle
   - JWT аутентификация
   - bcrypt для паролей

2. **Миграция данных**
   - Перенос из localStorage в PostgreSQL
   - Настройка миграций
   - Индексы для производительности

3. **Серверная проверка прав**
   - Middleware для проверки tenant isolation
   - Row Level Security policies
   - Проверка разрешений на каждом endpoint

4. **Полноценная система приглашений**
   - Отправка email через SMTP/SendGrid
   - Страница принятия приглашения
   - Механизм отзыва и повторной отправки

5. **Управление командами**
   - UI для создания/редактирования команд
   - Назначение сотрудников
   - Иерархия команд

6. **Личные кабинеты**
   - Кабинет руководителя с аналитикой команды
   - Кабинет финансового специалиста
   - Специализированные дашборды
