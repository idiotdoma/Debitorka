## P1 - Критические проблемы

### ✅ P1-1: Отчёт «Обещания оплаты» не передаёт данные в таблицу и экспорт

**Проблема:** В ReportsPage.tsx отчёт `promises` возвращал объект с полем `promisesData` вместо `data`, что приводило к пустой таблице.

**Исправление:**
- Изменена структура возвращаемого объекта на `{ data: promisesData, title, columns }`
- Добавлено форматирование `promisedAmountCents` в рубли через `formatCurrency()`
- Добавлено поле `promisedAmountFormatted` для отображения
- Добавлено поле `statusLabel` для человекочитаемых статусов
- Обновлён экспорт CSV/XLSX для обработки `promisedAmountCents`

**Файлы:**
- `src/pages/ReportsPage.tsx` (строки 65-92, 228-236)

---

### ✅ P1-2: Платёжный календарь может сдвигать сроки на день и не показывает просрочку

**Проблема:** 
1. Использовался `date.toISOString().split('T')[0]`, который сдвигает дату из-за часовых поясов
2. Просроченные события рассчитывались, но не отображались в календаре

**Исправление:**
- Заменён `toISOString()` на локальное форматирование даты через `getFullYear()`, `getMonth()`, `getDate()`
- Добавлено отображение просроченных событий в календарной сетке
- Обновлён `hasEvents` для учёта просроченных событий
- Добавлена визуальная индикация дней с просрочкой (красный фон)
- Обновлена легенда календаря

**Файлы:**
- `src/pages/PaymentCalendarPage.tsx` (строки 142-161, 443-515, 519-533)

---

### ✅ P1-3: Импорт с ошибочными строками помечается как полностью завершённый

**Проблема:** Статус импорта устанавливался как `completed`, даже если были ошибки в строках. Снимок создавался для неполных данных.

**Исправление:**
- Добавлен новый статус `partial` для импорта с ошибками
- Логика определения статуса:
  - `failed` - если нет успешных строк
  - `partial` - если есть и успешные, и ошибочные строки
  - `completed` - если все строки успешны
- Снимок создаётся только для статуса `completed` (полный успешный импорт)
- Обновлён тип `ImportBatch.status` в моделях
- Обновлён HistoryPage для отображения статуса `partial`

**Файлы:**
- `src/lib/importService.ts` (строки 362-398)
- `src/types/models.ts` (строка 471)
- `src/pages/HistoryPage.tsx` (строки 56-60)

---

### ✅ P1-4: Единая логика финансовых расчётов применяется не во всех разделах

**Проблема:** DashboardPage и другие страницы использовали собственные расчёты просрочки без фильтрации валют и отрицательных остатков.

**Исправление:**
- DashboardPage теперь использует `prepareDebtsForAnalytics()` для единой обработки данных
- Заменён ручной расчёт просрочки на использование `overdueDays` из `getActualDebtRecord()`
- Добавлены предупреждения о неподдерживаемых валютах и отрицательных остатках
- Добавлены поля `unsupportedCurrencyCount` и `negativeCount` в данные дашборда

**Файлы:**
- `src/pages/DashboardPage.tsx` (строки 1-7, 16-29, 60-68, 122-140)
